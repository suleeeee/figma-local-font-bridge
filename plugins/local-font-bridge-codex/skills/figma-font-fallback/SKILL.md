# Figma 本机字体回退

在 Figma MCP 实际报告字体加载问题后自动使用本流程，无需用户额外说“启动桥接”。不要把网络、权限或节点错误当作字体问题。无需为每次设计修改预先桥接。MCP 进程由宿主连接时启动；此技能不是宿主级错误拦截器，不能保证每个 AI 客户端都执行规则。

1. 记录失败字体的原始 family/style 和目标节点。确认哪些操作已成功；若前次调用可能部分完成，先读取目标状态，不要重复整批操作。
2. 调用 figma_bridge_status。已授权且插件连接时继续。插件未打开则请用户在 Figma Desktop 打开 Local Font Bridge；工具不可用则说明本地集成未启用，不能假装已连接。不要循环等待或使用普通 Figma MCP 启动社区插件。
3. 首次存在待授权连接时，取得用户对当前插件连接的明确授权，再调用 figma_connect_plugin。单次设计修改请求不是首次连接授权。多个请求需确认 requestId，不盲目批准。后续已授权自动重连不重复询问。
4. 调用 figma_check_font，使用准确原始 family/style。loadOk 为 false 时说明本机仍不能加载，停止依赖该字体的修改；不要自行替换字体、安装字体或转轮廓。
5. loadOk 为 true 时通过 figma_run_js 在桌面插件环境完成尚未完成的操作。先检查节点和文字片段，加载所有相关原字体，再编辑。保留范围样式、内容、布局及可编辑性。字体名称查询不等于成功加载。只在桥接验证成功后执行字体相关修改。
6. figma_run_js 默认须用户在 Figma 插件里逐次批准；用户自行开启「自动执行 AI 代码」后由插件按该授权直接执行。不要代用户开启或写入授权设置。被拒绝、超时或结果不明确时，不自动重发修改；先核对实际节点状态。字体检查成功不等于设计修改成功。
7. 修改后核对文字、字体、目标节点和必要的布局结果；区分真实设计验证与模拟测试。

本桥接不会上传字体文件，不会补齐未安装字体，也不会让其他 Figma MCP 调用自动访问桌面字体。插件必须保持打开。
